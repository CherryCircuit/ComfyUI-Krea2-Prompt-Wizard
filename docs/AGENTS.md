# Project Notes for Future Agents

This document is the handoff file for anyone (human or agent) who works
on this repository next. It covers current status, how to verify
changes, and the hard-won lessons that are easy to trip over again.

**Read this before changing code.** The companion documents
`ARCHITECTURE.md` (structure), `DEVELOPMENT.md` (commands and
conventions), `CHANGELOG.md` (history), and
`KREA2_PROMPT_RESEARCH.md` (weighting-syntax facts) fill in the details.

---

## 1. What this project is

A ComfyUI custom node pack: a transparent, database-driven visual
prompt builder for Krea 2 image generation. It never calls an LLM,
never makes network calls, and ships the backend and frontend in one
repo.

**Nodes (current contract — six nodes):**

| Class | Display name | Purpose |
|---|---|---|
| `Krea2PromptWizard` | Krea2 Prompt Wizard | Main V1 node. Outputs: `Prompt Output` (STRING), `Video Motion Prompt` (STRING), `Model` (MODEL), `Positive Conditioning` (CONDITIONING). Optional inputs include `expert_mode`, `model`, `clip`. |
| `Krea2SaveImage` | Krea2 Save Image | Saves PNGs with the prompt embedded as metadata (`krea2_prompt` chunk; optional plain-text `prompt` chunk mode for Timesaver / A1111 viewers). |
| `Krea2PromptSaver` | Krea2 Prompt Saver | Workflow-independent prompt record: appends every run to `ComfyUI/output/krea2_prompt_history.jsonl` and re-asserts metadata keys. |
| `Krea2WeightedPhrase` | Krea2 Weighted Phrase | Transparent single-phrase primitive. |
| `Krea2PromptAssembler` | Krea2 Prompt Assembler | Pure fragment assembler. |
| `Krea2PromptInspector` | Krea2 Prompt Inspector | Formats trace/state JSON into a report. |

**V1 frontend:** one workspace with Identity, Performance, Placement,
Environment, Camera, Lighting, Randomization and Advanced sections,
a sticky compiled-output dock and a focused editor. Character identity
and performance remain separate scopes. Four outputs: Prompt Output,
Video Motion Prompt, Model and optional Positive Conditioning. CLIP
opts into native conditioning; the first three slots remain compatible.
V2 remains a separate editor and is outside V1 overhaul changes.

## 4. Hard-won lessons (read before editing)

### 4.1 Subgraph blueprints: match the installed frontend envelope

The ComfyUI frontend (`Comfy-Org/ComfyUI_frontend`,
`src/stores/subgraphStore.ts`) loads global blueprints through
`SubgraphBlueprint.load()`. Each `subgraphs/*.json` file must be a
workflow envelope whose root graph contains exactly one node whose
`type` is the id of `definitions.subgraphs[0]`. The nested subgraph
still must pass the schema requirements: UUID `inputs` / `outputs` slot
ids, `version: 1`, and a `state` block.

- Blueprints are generated by `scripts/build_workflows.py`
  (`make_subgraph_basic` / `_transparent` / `_kj_nodes`); the
  calibration file reuses the basic blueprint.
- Do not write bare subgraph objects. Frontend 1.48.x rejects them with
  `Loaded subgraph blueprint does not contain valid subgraph`, producing
  the `Failed to load subgraph blueprints x4` toast.
- Node slot names inside blueprints must match the *current*
  `RETURN_NAMES` of the registered nodes.
- **Guarded by `tests/test_subgraphs.py`** — if you change node
  outputs or add a subgraph, extend it.

### 4.2 "Positive Prompt" in metadata viewers (Timesaver Artius Browser)

Viewers like Timesaver read the PNG `prompt` chunk and show it as the
Positive Prompt **only when it is plain text**. When it is the graph
JSON they bucket-scan nodes for a *literal* `text` input — **linked
inputs (`[node_id, slot]`) are skipped**. That is why workflows using
`Krea2 Prompt Weight` (a linked text) never show a Positive Prompt
while `CLIPTextEncode` workflows do. The text was always in the
metadata; the viewer just could not find it.

Two built-in fixes:

1. Wizard setting `prompt_metadata_override` (Node settings) — the
   wizard writes the resolved prompt as `extra_pnginfo["prompt"]`; the
   standard SaveImage writes the graph JSON first, then every
   `extra_pnginfo` key, and **PIL readers take the last chunk**
   (verified empirically). Timesaver then sees a plain-text `prompt`
   chunk, so the Positive Prompt shows.
2. `Krea2SaveImage.plain_prompt_metadata` input — writes a single
   clean plain-text `prompt` chunk.

**Guarded by `tests/test_loras.py::TimesaverCompatibilityTests`, which
ports Timesaver's actual extraction algorithm.** If Timesaver changes
its parser, update the port.

### 4.3 Never pass live DOM collections into `el()`

`state.mjs`'s `el()` treats a non-array `children` argument as a single
child. A live `HTMLCollection` (e.g. `grid.children` in a real browser)
is not an `Array`, so `el(..., grid.children)` crashed with
`appendChild: parameter 1 is not of type Node` **in real browsers
only** — the fake DOM's `children` is a plain array and masked the bug.
This caused the "Cast tab goes blank when adding a character" bug.

- Rule: convert collections to arrays (`Array.from(...)` or spread)
  before passing them to `el()`.
- The smoke-test fake now throws on non-node appends so this class of
  bug cannot hide again.

### 4.4 The frontend test harness has sharp edges

`tests/frontend_smoke.mjs` uses a hand-rolled fake DOM. Known
differences from real browsers:

- `innerHTML = ""` must clear children (the fake implements this).
  Re-render loops duplicate nodes otherwise.
- Text lives in child text nodes: `element.textContent` is empty; use
  the recursive `textOf()` helper.
- Compound class selectors (`"a.b"`) do not work in `findByClass`;
  search the base class and filter.
- `wizard.state` is a **stale reference** after `setState()` (the
  widget reassigns its internal `state` variable). Never mutate
  `wizard.state` in tests; use the public API (`setTab`,
  `applyResolvedState`) or read the persisted `stateWidget.value`.
- Clicks on handlers that call `event.stopPropagation()` must pass
  `{ stopPropagation() {} }`.

### 4.5 Frontend cache busting — bump `?v=` on every frontend change

`web/krea2_prompt_wizard_v3.js` imports helpers with `?v=N` queries
(check the current entrypoint). Bump N whenever you change any frontend file, and
update `tests/test_frontend_packaging.py::test_entrypoint_loads_helpers_before_registration`.
Stale browser caches have repeatedly caused "nothing changed / blank
node / old UI" reports that were really cached assets.

### 4.6 Keep the backend and frontend state schemas in sync

- `src/wizard.py::coerce_state` and `web/js/state.mjs::coerceState`
  both whitelist state keys and fill defaults. **Add every new state
  field to both.**
- The backend drops unknown keys when echoing resolved state, so
  frontend-only flags (e.g. `footer_open`, `show_concepts_tab`,
  `show_motion_prompt`) must be added to the backend coerce list or
  they reset after every job execution.
- `web/js/state.mjs::compilePreview` mirrors `src/compiler.py`
  (character fields, ensemble/separates rules, direction, motion
  draft). Keep the mirror in sync — the backend is the source of
  truth; the mirror powers the live preview.

### 4.7 The backend must not import `comfy` at module level

All `comfy.*` / `folder_paths` / `PIL` imports are lazy (inside
functions) so the test suite runs without a ComfyUI runtime. Tests
mock `folder_paths` via `patch.dict(sys.modules, ...)`
(see `tests/test_loras.py`).

### 4.8 Per-character LoRA reality

ComfyUI applies LoRAs to the whole model. The wizard's per-character
scoping is **textual**: trigger words compile only inside that
character's block, steering the LoRA's influence. Triggerless LoRAs
usually respond to their filename (auto-filled when picked). Without a
connected `Model` input the node warns instead of failing.

### 4.9 Legacy character fields

Pre-1.2.0 characters carry `clothing` / `subject` / `expression`
fields that still compile (backward compatibility), but the UI no
longer exposes them — which stranded users with uneditable prompt
text. Current behavior:

- Frontend coerce migrates `clothing` → `ensemble` when no new-style
  look is set (so it is editable / clearable).
- The compiler suppresses legacy `clothing` whenever `ensemble` /
  `clothing_top` / `clothing_bottom` are set.
- `expression` is suppressed when the character has direction.

### 4.10 `randomize_enabled_groups` early-return bug

It used to `return` early when `randomize_on_job` was missing, which
also skipped per-character randomization. It now defaults `flags` to
`{}` and always runs character-field and character-direction
randomization. If you add another randomization mode, do not
reintroduce an early return.

### 4.11 Settings toggles must call `render()`

The Node-settings toggles (Concepts tab, face guidance, motion
section, prompt metadata override) must call `render()` after flipping
state — calling only `renderNodeSettings()` leaves the rest of the UI
stale (this bit us once). The same pattern applies to any toggle that
changes what other tabs render.

## 5. Data model quick map

State (one JSON object in the `wizard_state_json` widget):

- `rows` — global concept rows (camera, lighting, environment, style).
  Custom lighting rows (`custom.light_*`) and the `custom.shot_distance`
  row are mirrors of the lighting panel / shot-distance slider and are
  regenerated by the frontend on every change; stale mirrors are pruned
  on load by `wizard.prune_stale_rows` (and the frontend `pruneStaleRows`
  in `web/js/state.mjs`), so the two must stay symmetric.
- `scene_sections` — lighting panel state (`lights`: id, label, angleDeg,
  distanceM (0.5-4 m), heightDeg (0-90), strength (0-3), color, enabled),
  `shot_distance` (camera slider -100..100), camera/lighting/environment
  subsection open flags, `stage_ground`.
- `characters` — cast members. Each has appearance fields
  (`sex`, `age`, `ethnicity`, `ensemble` / `clothing_top` /
  `clothing_bottom`, hair/face/body fields, `additional_info`),
  `profile_image` / `profile_image_name`, direction rows (`rows`),
  `position`, `face_guidance`,
  `lora_triggers` + `lora_name` / `lora_strength`, `interaction`,
  `randomize_fields` (appearance each-run pools),
  `randomize_direction_groups` (direction each-run flags),
  `expanded`, `additional_open`, and the legacy `subject` /
  `expression` / `clothing` fields (compiled only as fallbacks).
- `setting` — scene name + description.
- UI flags: `active_tab`, `footer_open`, `collapsed`, `show_work`,
  `show_concepts_tab`, `show_face_guidance`, `show_motion_prompt`,
  `prompt_metadata_override`, `settings_open`.
- `motion_prompt` / `motion_prompt_enabled` — LTX-2.3 motion output.

Direction groups (frontend `DIRECTION_GROUPS` in
`web/js/wizard_widget.mjs`, mirrored by `DIRECTION_GROUP_CATEGORIES`
in `src/job_randomizer.py`): `emotion`, `face`, `body`, `placement`.
Keep both in sync.

Presentation contracts (1.10.2): concept strengths are a 0.5-step grid
everywhere — `weight_mapping.snap_weight_step` and the `state.mjs`
mirror (`snapWeightStep`) must stay identical, including half-up
rounding; raw mode is the only unsnapped path. Concept rows render as
one −/label+value/+ pill (`preset_row.mjs`, `.krea2-pill` CSS); rows no
longer embed Phrase editors — concepts without a library preset edit
their phrase through a dialog. Wordy actions are icon buttons
(`W.iconButton`/`W.iconToggle` in `workspace.mjs`); "Queue workflow"
stays text. Concept columns use `auto-fit` so they respond to node
width, not the browser window.

## 6. Adding a new category or appearance field

1. `src/schemas.py`: add to `CATEGORIES` + `CATEGORY_LABELS`.
2. `scripts/build_default_library.py`: add presets, regenerate.
3. `web/js/state.mjs`: `CATEGORIES`, `CATEGORY_LABELS`, and the
   relevant `GROUP_CATEGORIES`.
4. Appearance fields additionally need:
   `CHARACTER_APPEARANCE` (widget), `CHARACTER_FIELDS` (compile
   mirror in state.mjs), `_CHARACTER_FIELDS` (compiler),
   `newCharacter()` defaults, and `coerceState` / `coerce_state`
   defaults on both sides.
5. Regenerate presets, validate, run the full suite.


## V1 overhaul invariants

Use the verification guidance in DEVELOPMENT.md and the reusable
prompt-wizard-validation skill. Backend preview and queue compilation
share the same contract; frontend fallback previews must not drive
exports. Materialize preserves the complete compiled snapshot in the
existing Prompt Assembler because legacy weighted primitives cannot
represent direct strengths and complete structural cast/scene text.
A missing current snapshot must leave the graph unchanged.

Preserve legacy rows in recovery rather than silently dropping them.
Migrate old light elevation into physical stage geometry. Seeded
randomization must repeat after serialization, obey locks and avoid
mutating protected scopes. Reuse existing preset storage and compiler
paths. Never replace development/runtime data with harness fixtures.
